# Timone

Timone is the meta-project steering agentic development across independent client/personal projects. Sessions run here at the timone root — never inside a managed project ([ADR-0007](doc/adr/0007-sessions-at-timone-root.md)).

## The essentials

- **Write plain English, everywhere. No metaphors.** ([Writing to the human](process.md#writing-to-the-human)) This is the first rule, not a style note. Short sentences. Common words. Say what a thing is, never what it is like. No images, no comparisons, no clever phrasing — not in chat, not in tickets, not in pull requests, not in `STATUS.md`, not in commit messages. "The gate ran and found four faults", never "the gate earned its keep". The reader does not read English as a first language, and a sentence he has to decode costs him time. No process vocabulary either: no stage numbers, no skill names, no words that only make sense to someone who has read `process.md`. A ticket carries what is being done, how far it has got, and what is needed from the human. Specifications, requirements and technical detail are **links** to committed artifacts, never text on a ticket. A comment is a few sentences, under 150 words.
- **The process** is defined in [process.md](process.md) — the single normative definition of every lifecycle stage, its artifact, and its gate. Stage skills under `.claude/skills/` implement it.
- **The harness routes, the human never does:** assume the human knows nothing about the process. A raw request concerning a managed project goes through `timone-triage` first, and the session invokes the routed stage skill itself — never require the human to name a stage or skill (naming one explicitly remains their right, not their duty). Every message addressed to the human ends with an explicit CTA on its own line or bullet.
- **Managed projects** are declared in `timone.yaml` and live as independent git repos under `projects/` (gitignored here). Materialize with `node dist/cli.js workspace sync`; inspect with `node dist/cli.js projects list`.
- **Target project:** every stage skill operates on one managed project — named in the prompt, or asked for; in daemon-triggered sessions it comes from the event. Skills touch only `projects/<name>/…`.
- **Client repos receive only process artifacts** (`doc/…`, `CONTEXT.md`). Never commit harness *files* — skills, `.claude/`, `.timone/`, `timone.yaml`, `process.md`, `standards/` — into a repository that is not Timone's own. The rule is about files: since [ADR-0019](doc/adr/0019-timone-authored-commits-carry-a-provenance-trailer.md) a provenance trailer does land in client history, deliberately, and that is not a harness file. **Timone itself is the one exception** ([ADR-0050](doc/adr/0050-timone-becomes-a-managed-project-once-the-run-path-is-fixed.md) D5): those files are Timone's own source, and a run working on Timone commits them like any other file. The test is the repository, never the project's name.
- **Every commit carries its provenance** ([ADR-0019](doc/adr/0019-timone-authored-commits-carry-a-provenance-trailer.md)): `Timone-Stage:` naming the stage that made it — or `interactive` when no stage was running — plus `Timone-Session:`, and `Timone-Run:` when a ticket drove it. The `SessionStart` hook tells every session its own id; an automatic check at `Stop` reports any commit that omits the trailer.
- **Standards** live in [standards/](standards/README.md): a mandatory baseline (accessibility per EAA, UI/UX) plus per-project stack entries. Only `Approved` entries are normative.
- Timone's own requirements are PRD-01/PRD-02 under [doc/specs/prd/](doc/specs/prd/); its decisions are ADRs under [doc/adr/](doc/adr/).
- **Timone's own defects are filed as [issues on this repo](https://github.com/fvermaut/timone/issues)**, labelled `bug` (plus `live-gate` when a live gate found it). The issue body points at the report section that recorded the finding; the report stays the record of what was observed, the issue tracks what is owed. These are not managed-project tickets — Timone is not in `timone.yaml` and no daemon picks them up.
