# Timone — Domain Glossary

> Ubiquitous language for Timone itself — terms only, no implementation details, no decisions.
> Managed projects each carry their own `CONTEXT.md`; this one is Timone's.

- **Gate** — a single human decision with one clear CTA: approve a PRD, approve a plan, confirm/decline/defer a feedback item. A gate decision is expressed as a reply on the ticket or PR — the ticket is the sole write-path for gate decisions.
- **Conversation** — a multi-turn interactive exchange with the human: a grilling interview, a wayfinder session, a prototype walk-through. Conversations run on a conversation channel. An acceptance that concludes a conversation (e.g. accepting the grill summary) is an in-conversation act; the session posts the accepted outcome to the ticket as the record.
- **Conversation channel** — the medium a conversation runs on: a chat application (Slack first, pluggable) or a terminal session via takeover. All channels sit behind one adapter seam; the terminal is the universal fallback every channel must reduce to.
- **Takeover** — the terminal fallback for a conversation: the ticket carries a CTA naming a `timone takeover` command; running it resolves what the ticket is waiting on, spawns the right stage session (the human never names a skill), and the session re-enters statelessly from the artifacts and the ticket thread.
- **Written answer** — the second way to answer a ticket waiting on a conversation: a plain comment, picked up by the daemon, which spawns the session that resolves the ticket. It needs no keyword and is read exactly as a gate reply is. Bounded at **one clarifying round** — an answer that leaves something open gets the remainder asked once, and a second unsettled answer hands back the takeover instead of a third question.
- **Handoff** — a stage session stopping part-way and asking the human for something it cannot settle on its own. It is a wait, not a failure: the run parks, the ticket says it is waiting on you, and a written answer or a takeover resumes the stage that stopped. Distinct from a failure, which is a stage that ended without an outcome or claimed work it did not do, and which only a retry moves.
- **Escalation** — a stage stopping because what it has been asked to do next is outside what that stage may do, most often an answer it read and understood and cannot act on. Distinct from a handoff in what ends it: a handoff waits for a reply and resumes on one, while an escalation waits for a person, because the stage already read the reply and was right about it. The run parks, the ticket says writing again will not move it and names the command that will, and that command opens a session bound to no stage. A ledger word only: the human never reads it.
- **Handback** — how an escalation ends: the session a person opened writes one comment saying the stop is cleared and naming the step the work carries on at, and the watcher reads it and starts that step. Its job ends there — it writes the words a decision needs (requirements, a decision record, a correction) and never the software, because building outside the loop gives up the piece-by-piece delivery, the visible cost, the provenance, the gates and the fresh-context check. A step the machinery cannot start is refused rather than guessed at, and the ticket says which name it could not use. Like **Escalation**, a ledger word: the human never reads it.
- **CTA (call to action)** — the explicit, visually set-off statement of what the human is being asked to do, ending every message the process addresses to a human.
- **Request** — what a human command leaves for the daemon when the daemon is the one holding the ledger: a single file naming the act asked for. The daemon applies it on its next cycle and stays the ledger's only writer; the command watches for the effect and reports that, not the errand. With no daemon holding the ledger, a command simply acts.
- **Preview** — a running instance of a pull request's branch, reachable at a URL posted on that PR, so a change can be looked at instead of read. Disposable by definition: it is created for a PR, replaced when the branch moves, removed when the PR ends, and never carries real data.
- **Preview adapter** — the seam that owns previews for a project: what a preview is built from, where it becomes reachable, and what its URL is. Timone states the PR and the commit it wants a preview of and asks the adapter to make that true; how, and at what address, is the adapter's to decide. Docker on our own host is the first; managed platforms are the same seam, not a different mechanism.
