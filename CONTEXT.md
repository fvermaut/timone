# Timone — Domain Glossary

> Ubiquitous language for Timone itself — terms only, no implementation details, no decisions.
> Managed projects each carry their own `CONTEXT.md`; this one is Timone's.

- **Gate** — a single human decision with one clear CTA: approve a PRD, approve a plan, confirm/decline/defer a feedback item. A gate decision is expressed as a reply on the ticket or PR — the ticket is the sole write-path for gate decisions.
- **Conversation** — a multi-turn interactive exchange with the human: a grilling interview, a wayfinder session, a prototype walk-through. Conversations run on a conversation channel. An acceptance that concludes a conversation (e.g. accepting the grill summary) is an in-conversation act; the session posts the accepted outcome to the ticket as the record.
- **Conversation channel** — the medium a conversation runs on: a chat application (Slack first, pluggable) or a terminal session via takeover. The terminal is the universal fallback every channel must reduce to. ✏ 2026-10-02 ([ADR-0060](doc/adr/0060-a-runner-decides-each-step-and-nothing-merges-without-a-persons-yes.md)): it no longer says that all channels sit behind one adapter. That adapter was deleted with the old code between steps.
- **Takeover** — a terminal session on a ticket, opened with `timone takeover`. While it is open, the runner does nothing on that ticket. When the run's step is a conversation, the session holds that conversation with the step's skill. When the session ends, the runner wakes and reads what it left on the ticket, so the session ends by writing there what it did and what should happen next. The human never names a skill. ✏ 2026-09-30 ([ADR-0060](doc/adr/0060-a-runner-decides-each-step-and-nothing-merges-without-a-persons-yes.md)): it used to resolve what the ticket waited on and start that stage's session.
- **Written answer** — removed on 2026-09-30 with the old code between steps ([ADR-0060](doc/adr/0060-a-runner-decides-each-step-and-nothing-merges-without-a-persons-yes.md)). Older records use it for a comment the old code read as the answer to a ticket waiting on a conversation. A named person's plain words on a ticket now wake the runner.
- **Handoff** — as a wait, removed on 2026-09-30 with the old code ([ADR-0060](doc/adr/0060-a-runner-decides-each-step-and-nothing-merges-without-a-persons-yes.md)). Older records use it for a stage that stopped part-way and parked its run on a person. The word still means a sub-agent's handoff notes: the section each slice of a phase appends to `phase-NN-handoffs.md`.
- **Escalation** — removed on 2026-09-30 with the old code ([ADR-0060](doc/adr/0060-a-runner-decides-each-step-and-nothing-merges-without-a-persons-yes.md)). Older records use it for a stage that stopped because it could not act on an answer, and waited for a person to open a session in the terminal.
- **Handback** — removed on 2026-09-30 with the old code ([ADR-0060](doc/adr/0060-a-runner-decides-each-step-and-nothing-merges-without-a-persons-yes.md)). Older records use it for the comment that ended an escalation and named the step to start. The runner now reads what a takeover left on the ticket.
- **Ask check** — removed on 2026-09-30 with the old code ([ADR-0060](doc/adr/0060-a-runner-decides-each-step-and-nothing-merges-without-a-persons-yes.md)). Older records use it for a small agent that made a question to a person shorter before it was posted. The runner now writes what a ticket needs with the whole run in view.
- **Remediation** — the cycle that follows a rejected pull request: the rejection re-enters triage as a new request, anchored on what the PR discussion found wrong, and runs the full loop again on a fresh branch. It is the only road for fixing work the human turned down — a rejected PR is never patched in place.
- **CTA (call to action)** — the explicit, visually set-off statement of what the human is being asked to do, ending every message the process addresses to a human.
- **Request** — what a human command leaves for the daemon when the daemon is the one holding the ledger: a single file naming the act asked for. Since 2026-09-30 a request is a cancel, or part of a takeover ([ADR-0060](doc/adr/0060-a-runner-decides-each-step-and-nothing-merges-without-a-persons-yes.md)). The daemon applies it — a cancel at once, even while its cycle is busy — and stays the ledger's only writer; the command watches for the effect and reports that, not the errand. With no daemon holding the ledger, a command simply acts. A retry request an older build left is settled once and reported, not carried out: `timone retry` was removed.
- **Preview** — a running instance of a pull request's branch, reachable at a URL posted on that PR, so a change can be looked at instead of read. Disposable by definition: it is created for a PR, replaced when the branch moves, removed when the PR ends, and never carries real data.
- **Preview adapter** — the seam that owns previews for a project: what a preview is built from, where it becomes reachable, and what its URL is. Timone states the PR and the commit it wants a preview of and asks the adapter to make that true; how, and at what address, is the adapter's to decide. Docker on our own host is the first; managed platforms are the same seam, not a different mechanism.
- **Initiative** — everything one ticket is asking for, from the first question to the last piece merged. A ticket hosts exactly one; the pieces it is built in are its chunks.
- **Piece** — what an initiative is cut into, and what the human reads as *step 2 of 3*. A piece is a thin path through every layer the work touches, working end to end, and it names only the requirements it delivers in full. It is never one layer of the product, and never a requirement another piece has to finish. A wide mechanical change across the codebase is the one shape allowed to be horizontal, and is sequenced as add the new form beside the old, move the callers, delete the old.
- **Chunk** — one piece of an initiative, and one run: its own branch, its own pull request, its own place in the queue. **Since [ADR-0040](doc/adr/0040-one-step-is-one-ticket-and-doneness-is-a-fact-about-a-ticket.md) a chunk is a *step ticket*, and one ticket no longer holds a sequence of them** — see **Step ticket** below, which is the word to use. The human never reads or types either word: they read *step 2 of 3*.
- **Step ticket** — one piece of an initiative, as its own ticket on the tracker. It is what a run belongs to now, so `timone cancel` and `timone takeover` name a step's number and not the initiative's (`timone retry` did too, until it was removed on 2026-09-30). It carries the `timone` mark, its parent, and the pieces it waits for as GitHub's own `blocked by` relation. The human reads *step 2 of 3 of #45*.
- **Map ticket** — the initiative's own ticket, once its pieces have been agreed. Its body is a list of links to its step tickets and nothing else, and it carries the `timone:map` label. No run is ever opened on it: the work belongs to the tickets it points at.
- **Hold** — the `timone:held` label. The machine puts it on a step when it starts one, and leaves it there if the step is dropped. A held step is one the machine will not take up again. Removing the label is how a person hands it back; it is the only thing in the system with no `timone` command behind it.
- **Dropped step** — a step whose work was thrown away with `timone cancel`. Its ticket stays open and holds the hold label, and the machine does not start it again. The two ways on are removing the label, or closing the ticket. **An initiative still finishes with a dropped step in it** — it closes saying how many pieces were really built, and works out which is which from whether a pull request was merged.
- **Chunk zero** — the specification-and-breakdown work an initiative starts with, merged into the default branch with no pull request once the human approves the list of pieces. ✏ 2026-09-30 ([ADR-0060](doc/adr/0060-a-runner-decides-each-step-and-nothing-merges-without-a-persons-yes.md)): it merges only when a named person's approval of the list is on record. When the runner skipped that approval, chunk zero does not merge on its own: the whole initiative is one piece, and reaches the person in one pull request. **It is not a run of its own**: it is carried by chunk 1, which then goes on to build the first piece on the same branch. So chunk numbers count *pieces*, and chunk zero has no number — the word names the work, not a row in the ledger.
- **Breakdown** — the ordered list of pieces an initiative will be built in, written once, approved once, and never rewritten as pieces land. Approving it opens one **step ticket** per piece, and which piece is next is then read from those tickets ([ADR-0040](doc/adr/0040-one-step-is-one-ticket-and-doneness-is-a-fact-about-a-ticket.md)) — never counted from the ledger. The file the human approved is the file that stays on the branch. A list that has grown since its approval is a re-proposal, and it stops the initiative until the human says whether to carry on. ✏ 2026-09-30 ([ADR-0060](doc/adr/0060-a-runner-decides-each-step-and-nothing-merges-without-a-persons-yes.md)): the runner may skip the approval, and says so on the ticket; no step tickets open then, and the initiative is built as one piece.
- **Runner** — the agent that decides what happens next in a run. It wakes when something happens on the run, reads it, and chooses the next step, with the written order of steps as its default. It acts only through the actions the machine gives it — start a step, message or stop a running one, post, hold, file a Timone issue, end the run — and never edits a file itself. Not a step: it runs none of the process's work, it decides which work runs.
- **Planner** — the agent that looks at all the tickets of one project that are ready to be built, and decides which can start building now and which must wait. A ticket waits for another when it needs that ticket's work and it is not merged yet, or when the two would change too many of the same files. When it holds a ticket back, it says on that ticket which ticket it waits for and why, and a named person can overrule it. Not the **runner**, which decides the next step of one run and sees only that run.
- **Update** — what the machine does to an open pull request after another pull request of the same project merged: it brings the branch level with the default branch, fixes any conflict, and runs the tests again. What it had to change is said on the pull request. It is not a rebuild: the work already done is kept.
- **Named person** — someone listed for a project as allowed to instruct its runner; the operator unless others are added. Only a named person's comment wakes the runner, and only a named person's yes can let work reach a default branch.
- **Departure** — a step of the **default order** that did not run, or ran out of order, in a run. The runner says so on the ticket when it happens; code lists every departure at the top of the pull request. A departure is allowed; a hidden one is the fault. Not an entry of the **departures record**, which is a different list.
- **Run record** — what the machine writes down about a run as it goes: each step that ran, each decision of the runner and its reason, each departure, and the cost so far. Written by the machine, never by the runner, because the departure list and the spending limit are worked out from it.
- **Default order** — the order of steps `process.md` writes down for each kind of ticket: a feature, a chore, a bug, a question, a question on a map, a research question, a map, a step ticket, a remediation. It is the runner's default, not a rule: the runner follows it unless it has a reason not to. A finished run is compared with it, so every step of it that did not run can be named as a **departure**.
- **Departures record** — the file `phase-NN-departures.md`, where the build, the check and delivery write down what they could not do as the plan or the requirements said: a plan step, a requirement, a check not run, a workaround. One dated entry each. Delivery quotes it in the pull request's own departures section. It is not the list of **departures** from the default order, which code writes above it on the pull request.
- **Probe** — a check script: a short program the checking step writes for one requirement, from the requirement's own words, and keeps under `doc/plans/phases/probes/`. Later checks run it again rather than write it again. In words to the human it is a **check script**. It is not the project's own test suite, which the builder writes.
- **Break run** — the run of a probe with the thing it checks broken on purpose, where the probe must fail. It proves the probe can catch a fault. The **real run** is the run on the build as it is, where the probe must pass.
